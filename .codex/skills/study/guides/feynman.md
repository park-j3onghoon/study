# feynman — Step 2 자기설명 강화 (Codex)

Execute 마지막에 "다른 사람에게 가르치기" 마이크로 단계. Codex 고유의 "산출물 강제" 패턴과 결합한다.

## 트리거

Step 2 Execute 2문항 모두 완료 직후. 사용자가 "feynman 패스" 입력 시 건너뛴다 (Quick Explain 모드는 자동 스킵).

## 5문장 설명 규칙

사용자에게 다음과 같이 요청:

> 방금 배운 내용을 **5문장 이내**로 다른 사람에게 설명해 보세요.
> 조건:
> 1. 전문 용어 1~2개까지만 허용. 그 이상은 풀어 쓰기
> 2. 비유 1개 이상 포함
> 3. "왜 그렇게 되는가" 한 문장 포함

사용자가 "완료"만 입력하면 통과시키지 않고 5문장 자체를 산출물로 요청한다 (Codex의 "완료 + 산출물" 규칙 그대로 적용).

## "모르는 학생" 페르소나 follow-up

가짜 학생처럼 행동하며 사용자의 설명에서 모호하거나 비약된 지점을 짚는다.

### 좋은 follow-up 패턴
- "어? 그 부분이 잘 이해 안 가는데, X를 좀 더 풀어 설명해 줄 수 있어?" (전문 용어 검증)
- "비유는 알겠는데, 실제로 그게 어떻게 일어나? 단계로 알려줘." (메커니즘 검증)
- "그럼 만약 Y 상황이면 어떻게 돼?" (엣지 케이스·응용 검증)

### 나쁜 follow-up (피할 것)
- 정답을 알면서 떠보는 질문 — 페르소나 깨짐
- 학습 내용 범위 밖 질문 — 사용자 혼란
- 한 번에 3개 이상 — 인지 부하

## 4단계 루프 (옵션, 시간 있을 때)

사용자가 더 깊이 가고 싶어 하면:
1. **설명**: 5문장 설명
2. **갭 분석**: follow-up에 답하면서 막힌 부분 자가 식별
3. **정제**: 막힌 부분만 다시 학습 (concepts 파일의 해당 섹션 Read)
4. **적용 테스트**: "이제 같은 비유로 새 예시 만들어 보세요"

## 저장

- 사용자의 5문장 설명을 concepts/{개념}.md의 `## Feynman 자기설명` 섹션에 추가 (날짜 표기)
- follow-up과 답변도 함께 저장
- 갭이 발견된 부분은 `## Q&A` 섹션에 별도 정리 (기존 Q&A 규칙)

## 도메인별 적용

- `tech`: 기술 메커니즘을 비유로 풀어 설명. 다른 개발자에게 페어 프로그래밍 중인 척
- `system-design`: "면접관이 처음 듣는 시스템" 가정. 트레이드오프를 한 문장에 담기
- `softskill`: "어색한 분위기를 어떻게 풀까?"처럼 시나리오를 실제 동료에게 조언하는 형식
- `process`: 신규 입사자에게 워크플로우 설명

## 시간 가이드

- 5문장 설명: 사용자가 자유롭게, 보통 1~3분
- follow-up 1라운드: 2~5분
- 4단계 루프(옵션): 추가 5~10분

Step 2 전체 시간이 30분을 넘기지 않도록 Feynman 단계는 5~10분 캡.
