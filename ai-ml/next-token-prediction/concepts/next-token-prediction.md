# Next Token Prediction

## 한 줄 정의

**주어진 텍스트(토큰 시퀀스)를 보고, 바로 다음에 올 토큰이 무엇일지 확률적으로 예측하는 것.**
이것이 ChatGPT, Claude 등 모든 LLM의 핵심 작동 원리이다.

---

## 비유: 문장 끝말잇기 달인

친구가 "오늘 날씨가 정말..."이라고 말하면, 당신은 자연스럽게 "좋다", "춥다", "덥다" 같은 단어를 떠올린다.
이때 "좋다"가 70%, "춥다"가 20%, "덥다"가 10% 정도로 그럴듯한 정도가 다르다.

LLM이 하는 일이 **정확히 이것**이다 — 다만 수십억 개의 문서를 읽고 훈련된 거대한 신경망이 이 "감"을 수학적 확률로 계산한다는 차이가 있다.

---

## 핵심 작동 원리 (5단계)

```
┌─────────────────────────────────────────────────────────┐
│                   Next Token Prediction                  │
│                                                         │
│  "오늘 날씨가"                                           │
│       │                                                 │
│       ▼                                                 │
│  ┌──────────┐    ┌───────────────┐    ┌──────────────┐  │
│  │ 1.토큰화  │───▶│ 2.임베딩 변환  │───▶│ 3.Transformer│  │
│  │(Tokenize)│    │ (Embedding)   │    │   처리       │  │
│  └──────────┘    └───────────────┘    └──────┬───────┘  │
│                                              │          │
│                                              ▼          │
│                  ┌──────────────┐    ┌──────────────┐   │
│                  │ 5.토큰 선택   │◀───│ 4.확률 계산   │   │
│                  │ (Sampling)   │    │ (Softmax)    │   │
│                  └──────┬───────┘    └──────────────┘   │
│                         │                               │
│                         ▼                               │
│                    "좋네요"  ← 선택된 다음 토큰           │
│                                                         │
│         ※ 이 과정을 반복 (Autoregressive Loop)            │
└─────────────────────────────────────────────────────────┘
```

### 1단계. 토큰화 (Tokenization)

입력 텍스트를 **토큰** 단위로 쪼갠다. 토큰은 단어가 아니라 **서브워드(subword)** 단위다.

```
"오늘 날씨가 정말" → [오늘, _날씨, 가, _정말]
"unhappiness"      → [un, happi, ness]
```

> **왜 단어 단위가 아닌가?** 모든 단어를 사전에 넣으면 어휘가 수백만 개로 폭증한다.
> 서브워드로 쪼개면 ~50,000개의 어휘로 거의 모든 텍스트를 표현할 수 있다.

### 2단계. 임베딩 (Embedding)

각 토큰을 고차원 벡터(숫자 배열)로 변환한다. 이 벡터가 토큰의 **의미**를 담는다.

```
"고양이" → [0.23, -0.91, 0.44, ..., 0.12]  (수천 차원)
"강아지" → [0.25, -0.88, 0.41, ..., 0.15]  ← 의미가 비슷하면 벡터도 가까움
```

### 3단계. Transformer 처리

핵심은 **Self-Attention** 메커니즘이다. 각 토큰이 다른 모든 토큰과의 관계를 파악한다.

```
"은행에서 돈을 찾았다"
  └── "은행"의 의미를 결정할 때 "돈"이라는 토큰에 높은 attention → 금융기관

"은행나무 잎이 떨어졌다"
  └── "은행"의 의미를 결정할 때 "나무", "잎"에 높은 attention → 식물
```

이 과정이 수십~수백 개의 레이어를 거치며 반복된다.

### 4단계. 확률 계산 (Logits → Softmax)

Transformer의 최종 출력은 **logits** — 어휘 전체(~50,000개)에 대한 점수 벡터다.

```
logits: { "좋네요": 5.2, "춥다": 3.1, "덥다": 2.8, "맑다": 4.5, ... }
         ↓ Softmax 변환
확률:   { "좋네요": 0.42, "맑다": 0.28, "춥다": 0.12, "덥다": 0.09, ... }
         (합계 = 1.0)
```

**Softmax**는 임의의 점수를 0~1 사이 확률로 변환하는 함수다.

### 5단계. 토큰 선택 (Sampling)

확률 분포에서 실제 토큰 하나를 고른다. 방법이 여러 가지:

| 전략 | 설명 | 특징 |
|------|------|------|
| **Greedy** | 확률 1위를 항상 선택 | 결정적, 반복적 |
| **Top-k** | 상위 k개 중 랜덤 선택 | k=50이면 50개 후보 |
| **Top-p (Nucleus)** | 누적 확률 p%까지의 토큰 중 선택 | p=0.9면 90% 커버하는 최소 집합 |
| **Temperature** | 확률 분포의 날카로움 조절 | 낮으면 보수적, 높으면 창의적 |

### 반복 (Autoregressive Loop)

선택된 토큰을 입력에 붙이고, **1~5단계를 다시 반복**한다.

```
Step 1: "오늘 날씨가 정말"        → "좋네요"
Step 2: "오늘 날씨가 정말 좋네요"  → "!"
Step 3: "오늘 날씨가 정말 좋네요!" → [EOS]  ← 종료 토큰
```

이것이 **자기회귀(Autoregressive)** 라고 불리는 이유: 자기 출력을 다시 입력으로 쓴다.

## 근본 원리: "왜 이것만으로 지능이 생기는가?"

### 1. 압축 = 이해

수조 개의 토큰에서 "다음 토큰"을 잘 맞추려면, 모델은 문법·상식·논리·세계 지식을 **자연스럽게 학습**해야 한다. 단순 암기로는 불가능 — 패턴을 **압축(generalize)** 해야 한다.

### 2. 단순한 목표, 놀라운 결과 (Scaling Law)

목표는 단 하나: **다음 토큰 예측의 오차(cross-entropy loss)를 줄여라.**
놀랍게도, 모델 크기·데이터·연산을 키우면 이 단순한 목표가 번역·코딩·추론까지 가능하게 한다.
이것이 **스케일링 법칙(Scaling Law)** 이다.

### 3. 한계도 여기서 온다

- **환각(Hallucination)**: "그럴듯한 다음 토큰"을 생성할 뿐, 사실 여부를 검증하지 않는다.
- **추론의 한계**: 진정한 논리적 추론이 아닌, 훈련 데이터의 패턴 재현에 가깝다.
- **한 토큰씩**: 전체 답변을 한 번에 계획하지 않고, 토큰 단위로 진행한다.
