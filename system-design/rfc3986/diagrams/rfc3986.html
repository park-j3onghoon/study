① URI 5컴포넌트 분해

scheme authority path query fragment
표준 예시 foo://user:pass@example.com:8042/over/there?name=ferret#nose 의 5컴포넌트 분해. //는 authority가 있을 때만, ?·#는 query·fragment를 여는 구분자.

② URI Reference 분류 트리

URI Reference는 URI (절대)와 Relative Reference의 합집합. Relative Reference는 첫 글자에 따라 network-path / absolute-path / path-noscheme / empty의 4개 production으로 갈라진다.

③ §5.2 Reference Resolution 알고리즘

§5.2 알고리즘의 if/else 트리. 위에서부터 차례로 체크 — scheme → authority → path 빈 여부 → path가 "/" 시작 → 그 외 relative-path. fragment는 항상 reference의 것을 쓴다 (어느 분기든 마지막에 덧붙임).

ReferenceResult주의

⑤ path-noscheme 콜론 모호성 비교

"this:that/foo" 라는 같은 문자열이 어떻게 해석되는가?

❌ 의도와 다른 해석
this:that/foo
첫 콜론 앞 → scheme = "this"
파서가 절대 URI로 해석. base 무시.
만약 "이건 상대 경로다" 가 의도였다면 버그.
✅ 의도대로 해석
./this:that/foo
첫 segment = . → relative-path
path = this:that/foo (base 기준 상대)
해결: 첫 segment에 콜론이 있으면 ./ 접두.

콜론 허용 위치

문자열해석이유
foo:bar/baz❌ scheme=foo첫 segment에 콜론. URI로 오인
foo/bar:baz✅ relative-path두 번째 segment의 콜론은 OK
./foo:bar/baz✅ relative-path첫 segment가 "."로 시작 → 안전
/foo:bar/baz✅ absolute-path"/"로 시작 → 콜론 무관
RFC 3986 §4.2: "첫 세그먼트가 콜론을 포함하면 scheme name으로 오인된다. 그런 segment는 dot-segment(./)를 앞에 붙여야 한다."
